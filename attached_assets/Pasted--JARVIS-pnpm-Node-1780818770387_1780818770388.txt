Задача: настроить и запустить импортированный проект JARVIS.
Контекст: монорепозиторий на pnpm (Node.js 24 + TypeScript), фронт React/Vite, сервер Express, база PostgreSQL (Drizzle ORM), генерация кода через Orval из OpenAPI. Владелец — не программист, объясняй просто и после каждого этапа коротко докладывай результат.
Твоя роль: настроить окружение и запустить. Код приложения не меняй — если что-то сломано, покажи мне полную ошибку и предложи решение, но не переписывай сам. OpenAI-ключ настраивать не нужно. Если команда с --filter не находит пакет — выполни pnpm -r list --depth -1, найди правильные имена и подставь.
Иди строго по этапам:
Этап 1. Зависимости. pnpm install (если ругается на lockfile — pnpm install --no-frozen-lockfile). Доложи результат.
Этап 2. База данных. Создай PostgreSQL и пропиши строку подключения в Secrets под именем DATABASE_URL. Доложи.
Этап 3. Генерация кода. pnpm --filter @workspace/api-spec run codegen (перезапись сгенерированных файлов — это нормально).
Этап 4. Схема в базе. pnpm --filter @workspace/db run push (создаёт таблицы, включая колонку health — светофор). Доложи.
Этап 5. Тестовые данные. pnpm --filter @workspace/scripts run seed (13 компаний с цветами светофора, сид идемпотентный). Доложи.
Этап 6. Проверка типов. pnpm run typecheck. Если ошибки — покажи полностью, код не правь, жди инструкций.
Этап 7. Запуск. Запусти оба сервера: API — pnpm --filter @workspace/api-server run dev (порт 8080); фронт — pnpm --filter @workspace/business-jarvis run dev (порт 5000). Можно через кнопку Run, но только после этапов 2–5. Дай ссылку на превью.
Этап 8. Проверка. Открой приложение и проверь: глобус во весь экран; узлы компаний разноцветные по светофору (зелёные/жёлтые/красные, а не все одного цвета); красные/жёлтые пульсируют ярче; есть легенда светофора со счётчиком; текст на русском.
⚠️ Если все узлы одного цвета ИЛИ вылетает ошибка про отсутствующую колонку health — остановись и сообщи мне (значит, свежие изменения не доехали из GitHub). Сам не чини.
Правила на весь процесс: код приложения не меняешь; после каждого этапа короткий доклад; при любой ошибке — полный текст + предложение исправления; этапы молча не пропускаешь.
