Задача: доработать экран «Лента» так, чтобы он работал как умная триаж-очередь, а не как набор карточек.

Сейчас лента красиво выглядит, но логика не доведена: рекомендации не привязаны к событию, цвет серьёзности не совпадает с содержанием, и непонятно, что происходит с карточкой после действия. Нужно исправить это по пунктам ниже.

1. Рекомендация должна генерироваться из самого события, а не быть общей заглушкой.
Сейчас на карточке про невыплату зарплат стоит рекомендация про «назначить замену и knowledge transfer» — это текст из другого кейса. Так нельзя. Сделай recommendation и defaultAssignee полями самого события. Привязка по типу:

Невыплата ЗП/платежа → «Запросить статус у банка + резервный платёж сегодня» → Финдиректор
Инцидент безопасности/авария → «Созвать экстренное совещание, остановить работы до проверки» → HSE/прораб
Уход ключевого сотрудника → «Назначить дублёра + knowledge transfer до даты выхода» → Руководитель направления
Срыв срока релиза/контракта → «Пересобрать план, эскалировать заказчику» → PM проекта
Жалоба клиента → «Связаться с клиентом в течение 2 часов» → Аккаунт-менеджер
Если данных под конкретную карточку нет — заглушка должна совпадать со своей карточкой по смыслу, а не быть скопирована с другой.

2. Правило цвета серьёзности — явное, по первому сработавшему условию сверху вниз.

🔴 срочно: невыплата ЗП/платежа в срок, остановка работ, штраф/предписание госоргана, авария, срыв релиза/контракта ≤ 7 дней, уход носителя критических знаний ≤ 14 дней.
🟡 важно: дедлайн 7–30 дней, отклонение KPI/бюджета, кадровый риск > 14 дней, жалоба клиента без эскалации.
🟢 инфо: статусы, отчёты, плановые события.
Проверка: «Зарплаты 312 субподрядчиков не перечислены в срок» по этому правилу = 🔴, а не 🟡. Сейчас она жёлтая при «срочно 0» — это баг, поправь.

3. Модель состояний — лента должна дренироваться до нуля.
Каждое решение убирает карточку из активной очереди:

«Запустить план» → карточка уходит в статус «В работе», создаётся задача, счётчик −1, автопереход к следующей карточке.
«Поручить» → открыть поле, после «Оформить» карточка → «Поручено», уходит из ленты, счётчик −1.
«Напомнить завтра» → карточка в очередь «Отложенные», вернётся завтра наверх, уходит из текущей ленты, счётчик −1.
«Далее»/«Назад» → только навигация, счётчик не меняется (это не решение).
«×» → выход, прогресс сохранён.
4. Счётчик срочно/важно/инфо считает НЕобработанные карточки. После каждого решения число падает. Позиция 1/9 — индекс в активной очереди без уже обработанных. Цель пользователя — довести все три счётчика к нулю.

5. Мелкие правки:

Развести два микрофона: нижний — голосовая команда по всей ленте, микрофон в поле «Поручить» — диктовка только в это поле.
Поле «Поручить» предзаполнять рекомендованным исполнителем (defaultAssignee) + показывать его чипом, чтобы поручение делалось в один тап.
Кнопку «Оформить» активировать сразу, как выбран исполнитель (не ждать ручного ввода).
«Внешн» сделать фильтром с явным вкл/выкл состоянием, а не просто меткой.
Критерий готовности: на каждой карточке рекомендация соответствует её содержанию; цвет ставится по правилу выше; после любого действия карточка исчезает из ленты и счётчик уменьшается; лента доводится до нуля.
