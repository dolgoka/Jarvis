Задача: довести логику экрана «Задачи» до идеала. Заказчик в этом тире делает одно — смотрит приёмку и за один взгляд принимает решение. Всё ниже подчинено этому.

1. Модель состояний задачи (замкнутая, без тупиков).
Канон жизненного цикла:
Поставлена → Принята в работу → Сдана на приёмку → [Принять → Выполнена(архив)] или [Вернуть → На доработке → снова Сдана на приёмку]

После «Принять»: задача уходит из «На приёмке» в новый раздел «Выполнено / Архив», счётчик приёмки −1, в хронику пишется шаг «Принята владельцем» с датой.
После «Вернуть»: задача переходит в «На доработке», возвращается исполнителю, и в хронику обязательно пишется шаг «Возвращена на доработку» с датой и текстом причины из поля «Причина возврата». Без записи причины в хронику возврат не оформляется.
2. Сортировка списка «На приёмке». Строго по порядку: сначала зависшие, затем по приоритету (Срочно → Средний → Низкий), затем по дедлайну (раньше — выше. Проверка: задача «Срочно + Зависла» должна быть первой в списке. Сейчас она внизу — это баг.

3. SLA и опоздания. Сравнивать дату «Сдана на приёмку» с дедлайном задачи. Если сдано позже дедлайна — показывать чип «сдана с опозданием N дней» на карточке и в детали. Пример: NDA с дедлайном «до 16 июн», сдан 18 июн → «опоздание 2 дня». Это важнее метки «Зависла» и должно быть видно сразу.

4. Порог «Зависла» зависит от приоритета. Задача считается зависшей, если ждёт решения владельца дольше порога: Срочно — 4 часа, Средний — 1 день, Низкий — 3 дня. Сейчас порог один на всех — сделать по приоритету.

5. ИИ-проверка результата для приёмки в один тап. В блоке «Что сделано» добавить:

кнопку «Открыть результат» — ведёт прямо на файл/ссылку из отчёта исполнителя (например /analytics/competitors-Q2-2026.xlsx);
строку ИИ-проверки: ИИ сверяет результат с сутью задачи и пишет вывод, например «ИИ сверил: в таблице 5 конкурентов, как в задаче ✓» или «ИИ: не хватает данных по 2 конкурентам ⚠». Это даёт владельцу принимать уверенно, не открывая файлы вручную.
6. Убрать дубль результата. Сейчас текст «Что сделано» повторяется в хронике на шаге «Сдана на приёмку». Оставить «Что сделано» основным блоком, в хронике показывать только событие + дату + ссылку «к результату», без копии текста.

7. Счётчик возвратов. Если задачу возвращали на доработку, показывать на карточке метку «возвращалась N×». Чтобы хронический пинг-понг был виден владельцу.

8. Мелкие правки.

Лейбл «3/» у исполнителей заменить на понятный «Участники: 3».
Раздел «В работе» для заказчика — только чтение, свёрнут по умолчанию (его задача — приёмка, не микроменеджмент).
Счётчики в шапке и секциях держать согласованными: «всего на приёмке», «из них зависших», после каждого решения — пересчёт.
Критерий готовности: список приёмки отсортирован (зависшие+срочные сверху); после «Принять» задача уходит в архив и счётчик падает; после «Вернуть» причина записана в хронику и задача ушла исполнителю; опоздание против дедлайна видно сразу; в «Что сделано» есть ИИ-проверка и кнопка открыть результат; владелец может принять задачу за один взгляд, не открывая файлы.
